## 1. الخلاصة

تم تنفيذ نظام محفظة زبون حقيقي + برنامج نقاط وفاء قابل للتهيئة، مربوطًا بالكامل بالخادم وقاعدة بيانات JSON الموجودة (بدون نظام موازٍ). كل عملية مالية تُمرَّر عبر معاملة واحدة `financeTx` (قفل ملفات مالية + قراءة حديثة من القرص + كتابة ذرّية داخلية)، وكل حركة تُسجَّل في دفتر غير قابل للحذف بمرجع فريد `ref` يمنع التكرار (النقر المزدوج، إعادة الطلب، إعادة إرسال الإشعار، تزامن الطلبات).

**لا شيء في هذه النسخة تجميلي**: لا أزرار وهمية، ولا طريقة دفع معطّلة تُعرض كمتاحة، ولا رصيد يُضاف قبل تحقّق بشري فعلي من التحويل.

## 3. واجهات API المضافة / المعدّلة

### الزبون (تتطلب رمز الزبون؛ الهوية من الرمز فقط)
| الطريقة | المسار | ملاحظات |
|---|---|---|
| GET | `/api/customer/wallet?lang&type&status&limit` | الرصيد، الإجماليات، الحركات بحالاتها، طلبات الشحن، النقاط والأرصدة وقيمة الـMAD، النصوص والشروط |
| GET | `/api/customer/loyalty` | برنامج النقاط فقط |
| POST | `/api/customer/wallet/loyalty/redeem` | `{points, requestId}` — خصم نقط + إيداع رصيد بمرجع واحد، مع منع التكرار |
| POST | `/api/customer/wallet/topups` | `{methodId, amount, reference, receipt?}` — ينشئ طلبًا **معلّقًا** فقط |
| GET | `/api/customer/wallet/topups/:id` (+`/receipt`) | حالة الطلب الحقيقية / الوصل (404 لغير صاحبه) |
| GET | `/api/payment-methods?context=checkout` | أصبحت تُضيف طريقة `wallet` للزبون المسجّل فقط، برصيده الحقيقي؛ الزائر لا يراها |

### الإدارة (صلاحيات منفصلة، تُنفَّذ على الخادم)
| الطريقة | المسار | الصلاحية |
|---|---|---|
| GET/PUT | `/api/admin/wallet/settings` | `finance.read` / `wallet.settings` |
| GET/PUT | `/api/admin/loyalty/settings` | `loyalty.read` / `loyalty.settings` |
| POST | `/api/admin/loyalty/preview` | `loyalty.read` — معاينة مسودة **دون حفظ** |
| GET | `/api/admin/loyalty/overview` · `/customers?q=` · `/customers/:id` | `loyalty.read` |
| POST | `/api/admin/loyalty/customers/:id/adjust` | `loyalty.adjust` (سبب إلزامي + مرجع اختياري) |
| POST | `/api/admin/customers/:id/wallet-adjust` | `wallet.adjust` |
| GET | `/api/admin/customers/:id/wallet-reconcile` | `finance.read` |
| POST | `/api/admin/loyalty/sweep` | `loyalty.adjust` — استحقاق المعلّق وانتهاء الصلاحية |
| POST | `/api/admin/orders/:id/refund` | `finance.write` — استرجاع طلب مُسلَّم (جديد) |
| PATCH | `/api/admin/topups/:id` | صار معاملة واحدة: تغيير الحالة + إيداع الرصيد + مرجع المزوّد |

### إنشاء الطلب
- `paymentMethod: "wallet"` = الدفع الكامل لقيمة المنتجات من المحفظة. إذا لم يكفِ الرصيد يعيد الخادم:
  `409 {code:"WALLET_INSUFFICIENT", wallet:{available, required, shortfall, currency}, canTopUp, canChooseAnotherMethod, message:{ar,fr,en}}`
  ولا يُنشأ طلب ولا يُخصم أي مبلغ.
- `useWallet: true|<amount>` (السلوك القديم) ما زال مدعومًا كمساهمة جزئية موثّقة.
- `Idempotency-Key` / `requestId` يعيد نفس الطلب (`duplicate: true`) عند التكرار.

## 4. تغييرات التخزين

لم تُغيَّر أي بنية قائمة ولم تُحذف أي بيانات. أُضيف/استُخدم:
- `data/loyalty.json` — `{settings, accounts:[{customerId, entries:[]}]}`: دفتر نقاط إلحاقي لكل زبون.
- `data/wallet_settings.json` — سياسة الشحن (حدود، رسوم، مبالغ جاهزة).
- `data/topups.json` — أُضيفت `fee`, `creditAmount`, `clientRequestId`, `provider{id,ref,verifiedAt}`, `creditedAt`, `walletBalanceAfter`.
- `data/customers.json` — كما هو: `walletBalance` + `walletHistory[]` (دفتر إلحاقي بمرجع فريد).
- `data/finance.lock` — قفل المعاملات المالية.
- سجل التدقيق `data/audit/` — كل تغيير إداري (الفاعل، الوقت، قبل/بعد، السبب، المرجع).
- `data/notifications.json` — إشعارات الزبون.

**مراجع الدفتر (Unique refs):** `topup:<id>` · `order:<id>:wallet` · `order:<id>:wallet_refund` · `order:<id>:refund` · `loyalty:earn:<orderId>` · `loyalty:reverse:<orderId>` · `loyalty:expire:<entryId>` · `loyalty:redeem:<requestId>` · `loyalty:adjust:…` · `adj:…`.

## 6. الواجهات

- **محفظة الزبون** `public/wallet/` (تصميم جديد بهوية SIYMON: خلفية داكنة، `#5DD62C` / `#337418`، بطاقات مستديرة، AR/FR/EN و RTL/LTR): بطاقة رصيد مع إخفاء/إظهار، شحن، السجل، إجماليات (مُضاف/مستخدم/مسترجع)، بطاقة النقاط (متاحة/معلّقة/مستخدمة/منتهية + قيمتها بالدرهم + تحويل بمعاينة فورية)، شروط وقواعد قابلة للطي، شاشة شحن (طرق فعلية فقط، غير المدعومة تظهر معطّلة بوسم «غير متاحة»، مبالغ جاهزة + مبلغ حر، الرسوم والرصيد الصافي قبل التأكيد، مرجع + وصل، رسالة نجاح «قيد المراجعة» وليست «تم الشحن»)، سجل مصفّى (شحن/دفع/استرجاع/تحويل نقاط/تعديل) مع تمييز بصري للإيداعات.

- **لوحة الإدارة**: صفحة «إدارة نقاط الوفاء» في القائمة (`#/loyalty`) — إعدادات البرنامج والقواعد، السقوف، الصلاحية، الحملات، معاينة AR/FR/EN قبل النشر، إجماليات البرنامج، بحث الزبائن بالمعرّف/الهاتف/البريد، تفاصيل (نقاط + محفظة + الدفترين + مطابقة)، تعديل يدوي بسبب إلزامي ومرجع اختياري.
- **عرض طريقة الدفع** في تفاصيل الطلب: الزبون، الإدارة، والمتجر (المحفظة/عند الاستلام/TPE + المدفوع من المحفظة + المتبقي عند التسليم + حالة الاسترجاع) — من لقطة الخادم لا من حساب المتصفح.

## 7. ما يحتاج مفاتيح/تكامل خارجي (لم يُنفَّذ لأنه غير موجود)

- **Stripe / بطاقات بنكية**: لا يوجد تكامل حقيقي في المشروع. تبقى `not_integrated` وتظهر «غير متاحة» في كل مكان — لا يمكن تفعيلها من اللوحة.
- **PayPal / بوابة دفع أونلاين**: غير موجودة بنفس المنطق.
- **التحويل البنكي (CIH/Wafacash/Cash Plus)**: تكامل يدوي بالكامل (مرجع + وصل + موافقة مشرف)؛ لا يوجد ربط API بنكي، لذلك لا يُضاف رصيد تلقائيًا — وهذا مقصود: **العودة إلى صفحة نجاح ليست إثبات دفع**.
- **Webhooks**: لا مزوّد يرسلها؛ الحماية من الإرسال المكرر مطبَّقة على مستوى المراجع الفريدة لكل إيداع/دفع/استرجاع، فتصبح فعّالة فور ربط أي مزوّد.
- **الدفع المختلط (محفظة + وسيلة أخرى)**: **غير متاح** حاليًا كما طلبت؛ المحفظة تدفع قيمة المنتجات كاملة أو يُرفض الطلب، والدفع الجزئي القديم يبقى موثّقًا على مستوى الـAPI فقط.

## 8. قيود معروفة

1. التخزين JSON بعملية واحدة: الذرّية مضمونة داخل العملية عبر قفل ملفات؛ التوسّع لأكثر من عملية/سيرفر يحتاج PostgreSQL مع `ref UNIQUE` وقفل صفوف.
2. قائمة النقاط المعلّقة تُستحق آليًا عبر مؤقّت الصيانة (`POST /api/admin/loyalty/sweep` متاح أيضًا يدويًا).
3. استرجاع الجزء النقدي من طلب مُسلَّم يُسجَّل كاسترجاع يدوي (المنصّة لا تستطيع تحريك نقد)، مع توثيق المبلغ والسبب والفاعل.
4. صفحات المتصفح (Playwright) غير قابلة للتشغيل في هذه البيئة؛ تم بدلًا من ذلك التحقق من مطابقة كل معرّفات الواجهة (42 معرّفًا) وكل حقول الـAPI التي تستهلكها الصفحة، إضافة إلى اختبارات E2E عبر HTTP.
